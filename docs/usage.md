# 使用指南

本指南说明怎样让 AI 接入资料、检索并给出有来源的回答，以及以后怎样更新资料。来源处理由项目 skill 执行；你负责指定范围、来源类型和操作目标，遇到需要取舍的问题时作出决定。

已有可用服务的使用者可以直接从[服务连接](#服务连接)开始。需要手动入口时查[源码说明](../src/README.md)，模块与数据流见[架构说明](architecture.md)。

## 使用须知

- **功能范围：** 初版提供来源导入和只读检索，不包含 Memory 提取、Wiki 生成或整理、向量或语义检索、服务端模型回答、人工审核 Web 界面、来源或知识写回接口及公网 OAuth。
- **来源范围与隐私：** 标准化来源经过选择和清洗，不是原始会话的无损归档；遗漏资料和被省略的事件不会自动补齐。派生问答的重复内容与循环佐证尚未专门治理，导入清洗和扫描也不保证内容完全脱敏。检索索引包含正文，应与来源资料一样按其内容妥善保护。
- **检索与回答：** 当前采用 SQLite FTS5 词法查询，召回效果受资料覆盖和实际用词影响，不保证每个问题都能完整召回。搜索摘要用于发现候选，回答依据来自进一步读取的正文；检索不到不能证明相关事情没有发生。答案由外部 AI 组织，仍可能漏读、误判或引用不准确，服务端不验证答案正确性。
- **执行限制：** MCP 任务有调用次数和证据预算限制，接口有响应大小、处理时限和并发限制，可能留下部分正文、截断明细或未解决项；具体约束以实际任务限制和[配置说明](../config/README.md#mcp-任务与执行账本)为准。
- **任务恢复：** 执行账本保存调用记录和来源定位，不保存证据正文；初版不提供跨会话、上下文压缩后的证据恢复或工具结果重放。
- **接口兼容：** MCP 仅实现声明的协议子集，客户端需支持结构化结果，不能假定任意客户端都兼容。旧接口字段、索引及账本格式不提供兼容层或自动迁移，升级需按[配置与部署](../config/README.md)处理。

## 首次使用

推荐将 [examples/sqlite-fts5.md](../examples/sqlite-fts5.md) 作为第一个导入对象，按[公开示例](../examples/README.md#在自己的工作区使用示例)完成第一次完整操作：准备环境与工作区 → 导入并构建发布索引 → 连接 MCP → 检索问答。来源导入和索引构建不依赖 MCP；尚无可用索引时，MCP 服务会启动失败，因此应在索引发布成功后再建立连接。

### 环境准备

当前要求 Python 3.10 或更新版本，以及启用 FTS5 的系统 SQLite。本机 stdio 支持 Linux/WSL，首次本机使用可以选择该方式；Windows 原生和 SSH 跨机 stdio 未纳入初版支持范围。

在仓库根目录安装依赖：

```bash
python3 -m venv venv
venv/bin/python -m pip install -r requirements.txt
```

使用支持项目 skill 的 AI 客户端打开仓库。两个 skill 位于 `.agents/skills/`；客户端不能自动发现时，让它加载[来源导入 skill](../.agents/skills/learn-corpus-ingestion/SKILL.md)和[检索 skill](../.agents/skills/learn-corpus-retrieval/SKILL.md)。在仓库内执行操作还应遵循 [AGENTS.md](../AGENTS.md)。

导入前按[工作区配置](../config/README.md#工作区配置)选择资料保存位置。推荐私有仓库 + `engine/` submodule，也支持非 Git 数据目录和同仓库默认目录；配置统一保存在 `config.json`，日常无需设置环境变量。原始输入目录在导入时显式指定。

### 资料导入

首次推荐导入仓库自带的 SQLite FTS5 示例文章。从代码目录打开 AI 客户端，明确文件路径与来源类型：

```text
使用 learn-corpus-ingestion，将 examples/sqlite-fts5.md 作为文章类型导入当前工作区，并构建发布本地检索索引。
```

完整的示例操作见 [examples/README.md](../examples/README.md#在自己的工作区使用示例)。也可以从自己的 Markdown 笔记或文章开始，或指定 Claude Code、Codex、受支持的网页会话导出；明确路径与来源类型，格式适配、筛选及验证由导入 skill 处理。

成功后，`sources/` 保存标准化来源，`meta/manifest.json` 登记已接受的来源，`meta/corpus/current` 指向已发布的检索索引。导入和索引构建是两个操作，上面的请求明确包含构建与发布。空语料不能直接构建可用索引。

如果出现 `review`，表示本批存在需要处理的审核问题；整批被阻断时，不提交本批新来源。已有索引仍可用，不代表本次导入已成功。

### 服务连接

先确认当前工作区的索引已构建并发布，再配置和连接服务。仅完成来源导入还不足以启动 MCP；服务不会自动导入资料或构建索引。

MCP 是 AI 客户端调用工具的协议。客户端（host）管理连接，可选择本机 stdio 或网络 HTTP；REST 则供直接调用 HTTP API 的程序使用。

| 使用方式 | 需要准备什么 | 配置说明 |
|---|---|---|
| 本机 stdio MCP | 本机索引、服务配置和可写账本目录；客户端启动服务子进程 | [本机 stdio 连接](../config/README.md#本机-stdio-连接) |
| HTTP MCP | 已运行的 HTTP 服务、MCP URL 和 Bearer 凭据 | [HTTP MCP 连接](../config/README.md#codex-http-mcp-连接) |
| REST | 已运行的 HTTP 服务、Bearer 凭据和 API 调用方 | [HTTP 服务配置](../config/README.md#http-服务配置) |

首次本机使用，可以让 AI 按以下目标完成一次性配置：

```text
参照 config/README.md，为当前仓库配置本机 stdio MCP。
```

服务与账本配置、目录权限及客户端示例统一见[配置说明](../config/README.md#服务配置与启动)。

建立连接后，让 AI 调用 MCP `status`，确认索引版本和账本状态，再完成一次搜索与正文读取。端口监听或工具列表出现，不足以证明目标资料已可检索。

### 检索问答

```text
使用 learn-corpus-retrieval 回答：<问题>。
```

检索 skill 会组织查询、读取命中上下文，并根据证据缺口决定是否继续。普通追问沿用相关任务和已读证据，你不需要手工管理查询、读取窗口或预算。

你应看到有来源信息的回答；资料不足、读取不完整或出现冲突时，回答应说明其影响并保留结论边界。

## 资料更新

继续向导入 skill 指定新增或变化的文件、来源类型，以及是否构建并发布本地索引。需要同步、重建或删除来源时，也明确本次范围和目标，由 skill 按对应规则处理。

导入后的资料要进入新索引才能用于检索。索引更新后需要重连本机 stdio 或重启 HTTP 服务；运行中的服务不会自动切换版本。具体操作见[索引更新与验证](../config/README.md#索引更新与验证)和[重启与重连](../config/README.md#服务重启客户端重连与旧索引保留)。

已有真实资料和运行配置时，按实际范围更新，不重复执行首次环境初始化。生产发布、服务重启另按实际部署范围处理；账本清理、归档、轮换和旧索引回收需要人工维护，见[运维检查清单](../config/README.md#运维检查清单)。

## 产物维护边界

以下文件与状态由程序维护，可以查看，但用户与 AI agent 不应手工编辑、覆盖、删除或用自写脚本、SQL 修补。需要变更时，由对应 skill 调用项目已有的导入、维护、构建或发布入口，保留登记、内容 hash、关系与日志的一致性。

| 产物或状态 | 维护方式与变更入口 |
|---|---|
| `sources/` 下的标准化 Markdown 与登记附件 | 由导入器写入；内容更新通过重新导入或重建，删除通过来源删除流程，不直接修补正文、改名或替换附件 |
| `meta/manifest.json` | 由导入及来源维护命令更新；状态调整使用 `update_source_status`，不手改 hash、路径、来源 ID 或状态绕过检查 |
| `meta/ingest.log` | 导入和来源删除流程追加变更事件；不补造、重写、删除或截断历史记录 |
| `meta/source-inventory.json`、`meta/source-review-queue.md` | 导入流程定向更新，或按明确范围执行 inventory/queue 重建；不手改快照、勾选队列或删掉问题来代替审核处置 |
| 检索索引中的 `corpus.sqlite`、`index.json`，以及发布包中的 `release.json` | 由索引构建与打包流程生成；资料变化后构建新索引，不编辑数据库或修改 hash、版本字段使校验通过 |
| 索引根目录下的 `current`、`previous` 链接 | 由本地构建的 `--publish` 或部署脚本维护；不手工改链接绕过发布流程，旧目录保留与清理按[运维说明](../config/README.md#服务重启客户端重连与旧索引保留)处理 |
| `mcp.ledger.path` 指定的执行账本数据库 | MCP 服务维护任务、调用及预算；通过 `get_retrieval_task` 和 `status` 查询，不手改任务状态或预算，不通过删除数据库消除错误；容量维护按[账本轮换](../config/README.md#账本容量检查与轮换)处理 |

代码、skill、说明文档和运行配置可按开发或配置目标修改。`meta/source-review-resolutions.json` 是审核处置输入，也允许按对应来源规则填写，但必须依据用户明确确认的决定，保留要求的原文 hash、locator 等绑定信息；agent 不自行编造处置来绕过 review。填写处置后重新运行导入流程，由程序更新队列与正式产物。

笔记或文章需要改正文时，修改其原始文件后重新导入；会话记录出现损坏或歧义时按来源规则处理，不改写原始记录掩盖问题。导入器始终只读原始输入。程序维护的产物也不都能重建：变更日志和任务账本包含历史状态，异常时保留现场，按[导入失败处理](#导入失败处理)或运维流程恢复。

手动 CLI 入口见[源码说明](../src/README.md#命令入口)，配置与凭据修改见[配置说明](../config/README.md)。路径为默认位置，指定其他输出路径时同样遵守维护边界。

## 常见问题

### 导入失败处理

先让 AI 报告失败阶段和本批受影响范围，再按导入 skill 处理：

| 情况 | 含义与下一步 |
|---|---|
| 准备或预览失败 | 准备未完成，不能假定辅助状态已更新；核对来源类型、文件及本次范围 |
| 审核阻断 | 正式调用已更新本批辅助分析，但不提交本批来源；确认需要取舍的问题后，按同一范围重新导入 |
| 提交前文件或登记变化 | 准备时的快照已失效；检查其他写入者并重新准备，不绕过校验 |
| 写入异常或中断 | 可能已有部分产物落盘；保留现场，暂停继续导入、构建与发布，先核对实际状态 |

原始输入保持只读。已有来源不因本批失败就需要删除；正常正式导入已定向更新辅助分析，一般不需要再做一次全量盘点。

来源导入没有整批磁盘事务或通用自动恢复，写入中断需先核对现场。重跑不保证补记此前缺失的变更日志，也可能遇到未登记文件冲突。发现日志缺口、孤立文件或不确定的覆盖关系时，应明确报告范围并由你决定恢复方案，不手工修补登记或日志，不以删除文件或 Git 回退掩盖问题。

`check_corpus` 只检查、不自动修复；即使限制 `--sources`，仍包含全局 manifest 和 ingest log 检查。对真实语料做全量检查前，需明确检查范围。

### 检索无结果或证据不足

| 现象 | 如何判断 |
|---|---|
| 搜索没有命中 | 确认资料已进入当前索引，尝试原文中的词、语言或标识；词法未命中不能证明历史中没有发生 |
| 导入后仍查不到新资料 | 按[索引更新与验证](../config/README.md#索引更新与验证)核对发布结果和服务使用的版本 |
| 命中摘要却无法支持回答 | 让 AI 读取正文并核对发言角色、时间和上下文 |
| 正文只返回一部分 | `partial_budget` 表示读取窗口受预算限制，未读部分仍是证据缺口 |
| 出现 `budget_exceeded` 或任务额度耗尽 | 根据已读内容回答并说明限制；由检索 skill 判断下一步，不为规避额度反复创建同一目标的任务 |
| 重复查询或读取被拒绝 | 原任务已尝试该调用；复用已有结果，围绕实际证据缺口继续 |
| 任务记录里有检索单元，但无法引用正文 | 账本只保存定位元数据，不能从记录补造证据 |
| 助手建议被写成用户已实施 | 让 AI 核对实际角色和正文，纠正证据归属 |

### 连接与服务异常

连接参数、索引校验、权限以及 HTTP 错误见[运行问题排查](../config/README.md#运行问题排查)。服务失败或调用被拒绝不能解释为“资料中没有证据”。需要反馈时，按下节[反馈问题](#反馈问题)整理信息。

## 反馈问题

说明期望行为、实际结果、客户端连接方式和错误阶段。保留安全的错误码、请求标识和索引版本；对外反馈前去除凭据、查询正文、私人路径和来源内容。

需要核对原文或运行配置时，在私有环境中按实际范围处理。任务执行统计可用于诊断工具行为，但不能恢复证据正文。
